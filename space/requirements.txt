# SoloScribe on Hugging Face Spaces — Linux, CPU only, Python 3.10.
#
# Read space/README.md before changing anything here. Four of these lines are
# load-bearing for reasons that are not obvious from the package names, and one
# of them (setuptools) will look like leftover cruft to anyone tidying up.

# --------------------------------------------------------------------------
# torch, CPU build
# --------------------------------------------------------------------------
# PyPI's default `torch` wheel for Linux bundles the CUDA runtime and runs to
# several gigabytes. The Space has no GPU, so it is fetched from PyTorch's
# CPU-only index instead: 183 MB rather than several GB, which is most of the
# difference between a build that finishes and one that does not. The `+cpu`
# local version is what forces that index — dropping it silently returns you to
# the CUDA wheel. Verified present for cp310 and cp311 on
# download.pytorch.org/whl/cpu as manylinux_2_28_x86_64.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.13.0+cpu

# --------------------------------------------------------------------------
# the transcription model
# --------------------------------------------------------------------------
# Pinned to 0.4.0 because soloscribe/transcribe.py is written against that
# version's source and cites its line numbers — the shape of `predict`, the
# units of the pitch bends, the meaning of `amplitude`. A minor bump could move
# any of those quietly.
#
# The [onnx] extra installs onnxruntime. It does NOT by itself make ONNX the
# backend: basic-pitch picks a model format at import time in a fixed order —
# TensorFlow, CoreML, TFLite, ONNX (basic_pitch/__init__.py:81-88) — from
# whatever is importable, and its OWN dependency markers decide what that is
# (basic_pitch-0.4.0.dist-info/METADATA):
#
#   Linux + Python 3.10   ->  tflite-runtime      (a hard dependency)
#   Linux + Python 3.11+  ->  tensorflow<2.15.1   (a hard dependency, 475 MB,
#                                                  and it pins numpy<2)
#   macOS                 ->  coremltools
#
# That is why README.md pins python_version to 3.10 — 3.11 would drag half a
# gigabyte of TensorFlow in and drag numpy backwards with it. onnxruntime is
# here so app.py can choose ONNX explicitly (pin_transcription_backend), that
# being the one Linux backend this repo has actually been run against.
basic-pitch[onnx]==0.4.0

# --------------------------------------------------------------------------
# setuptools: LOAD-BEARING, DO NOT RELAX
# --------------------------------------------------------------------------
# basic-pitch requires resampy<0.4.3, and resampy/filters.py:50 does
# `import pkg_resources`, which setuptools 81 removed. setuptools' own
# deprecation warning says it outright: "Refrain from using this package or pin
# to Setuptools<81". Without this, transcription dies on the first resample
# with a bare ImportError.
setuptools<81

# --------------------------------------------------------------------------
# the audio and notation stack
# --------------------------------------------------------------------------
# Exact pins where the repo's code is written against a specific API, floors
# where it is not. numpy, scipy and matplotlib are deliberately UNPINNED: the
# versions this repo runs on locally (numpy 2.4.6, scipy 1.17.1, matplotlib
# 3.11.1) all declare requires-python >=3.11, so pinning them here would make
# the build unsatisfiable on the 3.10 runtime chosen above. pip resolves the
# newest 3.10-compatible release of each.
librosa==0.11.0
soundfile==0.14.0
pretty_midi==0.2.11.post0
mido==1.3.3
mir_eval==0.8.2
PyGuitarPro==0.11
numpy
scipy
matplotlib

# --------------------------------------------------------------------------
# guitar isolation (only runs when the checkbox is ticked)
# --------------------------------------------------------------------------
# soloscribe/separate.py is written against demucs 4.1.0's API and cites its
# line numbers, so this is pinned for the same reason basic-pitch is. The model
# weights are NOT in the package — they download on first use, which is why the
# first isolated transcription is slower than the ones after it.
demucs==4.1.0

# --------------------------------------------------------------------------
# the web front end
# --------------------------------------------------------------------------
# Keep in step with `sdk_version` in README.md — Spaces installs the version
# named there, and a mismatch means the app is tested against one Gradio and
# served by another.
gradio==6.22.0
